# Scope Tier Model v0.4

**Status:** Draft for Architecture Freeze  
**as-of:** 2026-09-08

## 1. 目的

「全部の証券会社に必須な機能」と「取扱業務によって必要になる機能」と「証券基幹の外側に置く周辺System」を混同しないため、Scopeを3段階に分ける。

---

## 2. Tier定義

### Tier A — Core

日本の総合証券会社の基幹/バックオフィスとして、原則必須とする業務責務。

### Tier B — Conditional

取扱商品・取引・チャネル・業務モデルによって必要となる業務責務。

### Tier C — Adjacent

証券会社として必要な場合があるが、本リポジトリでは証券取引基幹の外側に置き、I/FをAuthorityとする領域。

> Tierは「重要度」ではない。例えば会社全体Risk管理は非常に重要だが、証券取引基幹そのものの責務境界からは外側に置けるためTier Cとなる。

## 6. 重要原則

1. Tier A/Bともに「論理サブシステム」であり、必ず別アプリ/別DBに実装するという意味ではない。
2. 1つの製品/Packageが複数SSを実装してもよい。
3. 1つのSSを複数Serviceに分割してもよい。
4. Architecture Reviewでは物理構成ではなく、業務責務とData Authorityを先に固定する。
5. v1.0 Freeze前にTierを最終確定する。

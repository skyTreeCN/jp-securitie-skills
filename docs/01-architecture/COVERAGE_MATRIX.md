# Coverage Matrix v0.3

**Status:** Draft for Architecture Review  
**as-of:** 2026-09-08

本書は `サブシステム × 取引種別 × 商品` の3軸でCoverageを確認し、サブシステムの漏れ/重複を検出するための総体設計資料である。

---

## 1. Coverageの考え方

- サブシステム = 機能
- 取引種別 = 何をするか
- 商品 = 何を取引するか

業務要件は `SS × TR × PR` の交点で定義する。

例:

`SS26 譲渡益税 × TR01 現物売却 × PR01 国内株式`

## 5. Coverage Gapの判定

以下の場合はサブシステム追加を検討する。

1. 複数商品・複数取引に共通する独立した業務Authorityが既存SSに置けない。
2. 独立した状態機械/残高/法定帳簿を持ち、既存SSへの包含で責務が不自然になる。
3. 外部制度上独立した重要I/F/締め/照合を持ち、既存SSではBoundaryが破綻する。
4. 1つのSSが異質なAuthorityを複数持ち始める。

逆に「商品が違う」「取引名称が違う」だけではサブシステムを追加しない。

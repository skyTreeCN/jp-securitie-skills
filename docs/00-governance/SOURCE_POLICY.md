# 出典・根拠管理ポリシー

## 1. 目的

証券業務 Know-how を「AIが答えられる知識」ではなく、**設計・テストに使える根拠付き業務規則**として管理する。

## 2. 出典ランク

| Rank | 種別 | 例 | 用途 |
|---|---|---|---|
| A | 法令 | e-Gov法令、所得税法、租税特別措置法、金商法 | 法的根拠 |
| B | 主管官庁の公式解釈 | 国税庁通達/Tax Answer、金融庁監督指針 | 制度解釈 |
| C | 公式様式・仕様 | 国税庁法定調書様式、e-Tax仕様、JASDEC/JPX仕様 | 項目/レイアウト/IF |
| D | 公的・業界インフラ | JPX、JSCC、JASDEC、日証協 | 市場/決済/業界実務 |
| E | 業界公開資料 | 証券会社、銀行、ベンダーの公開資料 | 実務補助 |
| F | 内部Know-how | 設計書、QA、障害票、テスト、業務有識者 | 実装・運用知識 |

## 3. Rule記述単位

各ルールに以下を持つ。

```yaml
rule_id: TAX-CGT-001
status: confirmed
as_of: 2026-09-08
effective_from: YYYY-MM-DD
effective_to: null
authority_rank: B
source:
  title: ...
  url: ...
  locator: "該当節/条文/ページ"
```

本文:

- 業務ルール
- 適用条件
- 除外/例外
- 計算
- INPUT
- OUTPUT
- 他サブシステムへの影響
- テスト観点
- 出典

## 4. 禁止事項

- ベンダー公開説明から、非公開の内部サブシステム名・DB・IF仕様を推定して「事実」と記載しない。
- 二次資料だけで税率・期限・法定帳票項目を断定しない。
- 適用年月を持たない税制ルールを固定値化しない。
- 現行制度と将来施行制度を混同しない。

## 5. 改正対応

税制・NISA・決済制度・法定帳票は変更が多いため、Ruleは `as_of` と `effective_from` を必須とする。

特に2027年1月以降は、防衛特別所得税の導入と復興特別所得税率の変更が予定/施行規定化されているため、税率ロジックは年月日でバージョン管理する。

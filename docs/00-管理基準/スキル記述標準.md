# スキル記述標準 0.2版

## 0. 文書命名規則

- 設計書・管理文書の**ファイル名と文書タイトルは日本語で統一する**。
- `OVERALL_DESIGN.md`、`SYSTEM_LANDSCAPE.md` のような英語ファイル名を新規作成しない。
- 例: `全体設計書.md`、`システム全体構成図.md`、`業務機能一覧.md`。
- SS/CS/TR/PR等の管理ID、正式な外部制度名、プロトコル名、Agent Skillの機械識別に必要な名称は例外とする。
- 文書本文も日本語を基本とし、英語用語を使用する場合は業界標準・技術標準として必要な場合に限定する。

## 1. 分類

Skillはサブシステム単位で管理する。

```text
skills/
  subsystems/SSxx-<slug>/   # 業務サブシステム
  common/CSxx-<slug>/       # 共通系サブシステム
```

取引種別（TRxx）と商品（PRxx）はSkillディレクトリ階層には混在させず、各サブシステムSkill内で適用Coverageとして参照する。

基本式: `サブシステム × 取引種別 × 商品`

## 2. 各Skillの標準構造

```text
SSxx-<slug>/
  SKILL.md
  business-rules.md
  input-output.md
  interfaces.md
  transactions.md
  products.md
  reports/
  sources.md
```

## 4. Mermaid

状態遷移、データ流、サブシステム関係は Markdown 内に Mermaid で記載する。

```mermaid
flowchart LR
  A[INPUT] --> B[Business Rule]
  B --> C[OUTPUT]
```

## 5. 成熟度

- `L0 Skeleton`: 役割と境界のみ
- `L1 Overview`: 主要業務・I/O・関係
- `L2 Rule`: 業務規則、計算、例外、出典
- `L3 Design-ready`: 項目・状態・帳票・IF・テスト観点まで
- `L4 Verified`: 複数一次情報 + 実案件Know-howで検証済み

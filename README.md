# jp-securitie-skills

日本の証券会社向け基幹システムの**業務Know-how / システムKnow-how**を、要件定義・設計・テスト・障害分析で再利用できるSkillとして体系化するリポジトリ。

## 文書体系

```text
docs/
  00-管理文書/
    01-管理基準/
    02-計画・進捗/
    03-レビュー記録/
    04-移行記録/

  10-設計文書/
    01-全体設計/
    02-サブシステム別設計/

skills/
  subsystems/
  common/
```

## 文書区分原則

- **管理文書**: 方針、基準、計画、進捗、レビュー、検証、凍結、移行の記録。
- **全体設計書**: システム全体の機能分割、関係、データ正本、外部関係、業務一貫処理等。
- **サブシステム別設計書**: 各SS/CSの業務機能、規則、入出力、状態、計算、インターフェース、帳票、例外等。
- 設計内容の正本は `docs/10-設計文書/` 配下とする。

詳細は `docs/00-管理文書/01-管理基準/文書分類基準.md` を参照する。

## 基本分類

本リポジトリでは次の3軸を混在させない。

1. サブシステム: 業務機能・責務
2. 取引種別: 何をする取引か
3. 商品: 何を取引するか

基本座標:

`サブシステム × 取引種別 × 商品`

## 現在の全体設計範囲

- 業務サブシステム: SS01～SS42
- 共通サブシステム: CS01～CS06
- 取引種別: TR01～TR11
- 商品: PR01～PR11

## Know-how整理原則

- 各業務規則に適用条件、例外、計算、システム影響を記載する。
- 入力・出力は具体的な業務項目まで定義する。
- 帳票は帳票名だけでなく、レイアウト、項目、出力契機、交付先/提出先まで整理する。
- 制度・税務・市場ルールは一次情報を優先し、出典と適用時点を明記する。
- 社内経験則は制度上の根拠と分離して管理する。
- 設計書・管理文書の名称は原則として日本語とする。
